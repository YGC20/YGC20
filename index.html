차량 번호판 인식 및 문자 탐지 프로그램 OCR

2025.03 – 2025.11 · 5인 팀 (졸업작품)

GitHub ↗

동아대학교 × 부산 사하구청 현장미러형 연계협업 프로젝트. 시민 신고 사진에서 차량 번호를 추출해 행정 처리용 엑셀 보고서를 자동 생성하는, 외부 전송 없이 100% 로컬로 구동되는 윈도우 애플리케이션.

Contribution

  • 백엔드·OCR 파이프라인 담당: Flask REST API와 YOLOv5 번호판 탐지 → 4점 투시 변환 → 3중 OCR 병렬 실행 흐름을 구현하고 모델을 통합 (저장소 전체 92커밋 중 66커밋)
  • 전처리 설계: Canny 컨투어 기반 투시 보정(실패 시 이진화 + minAreaRect 폴백), CLAHE·Bilateral 필터로 다양한 촬영 각도·조도 대응
  • 인식 정확도 고도화: EasyOCR 2종과 자체 학습 Custom CRNN을 앙상블하고, 다수결 → 한국어 모델 우선 → 신뢰도 비교 → 한글 패치의 4단계 폴백으로 최종 번호 선택
  • 오인식 보정: B↔8, O↔0 등 오인식 패턴을 분석해 정규표현식 기반 2차 보정 로직 구현
  • 사용 편의: GUI 수정 모드와 엑셀·JSON 내보내기, PyInstaller exe 패키징으로 GPU 없는 관공서 PC에서도 실행되도록 최적화

Results

  • 처리 속도 단축: 수작업 1시간 36분 → 4분 18초 (385장 기준)

Review

  • 보안상 실제 민원 데이터를 쓸 수 없어 주차장 등에서 다양한 환경의 번호판을 직접 촬영해 학습·검증 데이터셋을 구축했고, 라이브러리 버전 충돌을 막으려 개발 환경을 표준화해 Notion에 기록했습니다.
  • 현장 데이터 특성을 분석하고 전·후처리 로직을 정교하게 설계하는 일이 최종 성능에 더 큰 영향을 미친다는 점을 깨달았습니다.
  • 제한된 하드웨어 자원(GPU 부재 등)에서 최적화된 로컬 모델을 구축하며 폐쇄망 환경에서의 SW 개발 역량을 길렀습니다.

수영장 청소 보트 프로젝트 BoatControl

2024.04 – 2026.09 (진행중)

GitHub ↗

객체 인식으로 수면의 쓰레기를 자율 수거하는 보트 제어 시스템. 노트북(웹캠 캡처 + ONNX Runtime YOLOv10n 추론)과 Zybo Z7-10(PetaLinux 2017.4, 모터·초음파 센서 제어)을 이더넷으로 직결하고 UDP로 탐지 결과를 주고받는 2-장비 구조. 2026-09-26 기준 실제 보드에서 부팅부터 커널 모듈 로드, vision ↔ boat UDP 통신까지 소프트웨어 스택 전체를 검증했습니다.

Contribution

  • 아키텍처 3단계 전환: 라즈베리파이 단일 보드(Python) → C++ 전환 → 노트북(영상 처리)·Zybo 보드(모터 제어) 2-장비 구조로 직접 재설계
  • vision ↔ boat 통신 프로토콜 설계: 고정 크기 UDP 패킷(DetectionPacket, 204바이트, 포트 5555)으로 한 데이터그램 = 한 프레임 탐지 결과가 되도록 구현. 재전송이 필요 없는 덮어쓰기성 제어 데이터라 TCP 대신 UDP 선택
  • 리눅스 커널 드라이버 직접 구현: 모터(motor_driver)는 ioctl 기반 캐릭터 디바이스로, 초음파 센서(echo_driver)는 trigger 출력과 엣지 인터럽트 기반 펄스 폭 측정(40ms 타임아웃)을 모두 커널 모듈이 전담
  • 설계 문제 해결: PetaLinux 2017.4 커널(~4.9)이 libgpiod 2.x가 요구하는 GPIO uAPI v2(5.10+)를 지원하지 않아 유저스페이스 하이브리드 구조가 동작하지 않음을 확인하고, trigger 핀까지 커널 모듈이 소유하도록 구조를 변경
  • 주행 판단 로직: 초음파 거리 60cm 미만이면 정지, 아니면 최고 confidence 대상의 중심 좌표 차이로 전진/좌/우 결정, 탐지가 없으면 랜덤 탐색
  • 부팅 환경 구축 및 검증 용이성: Docker에서 PetaLinux 빌드·커널 모듈 레시피 등록·SD카드 수동 파티셔닝으로 실보드 부팅. stub/dev 이원화로 실장치 없이도 로직 검증 가능

Review

  • 논리적 코드가 실제 하드웨어의 물리적 동작으로 변환되는 제어 루프를 직접 구현하며 신호 처리와 타이밍 동기화의 중요성을 체득했습니다.
  • 남은 작업은 HC-SR04 echo(5V) 라인의 레벨시프터 배선, 모터 실주행 테스트, 커스텀 쓰레기 탐지 모델 학습입니다. 현재 상태와 한계를 있는 그대로 문서화(진행 기록 · 빌드/실행 가이드)하며 이어가고 있습니다.

테트리스 구현 프로젝트 tetrisStudy

2026.06 – 2026.08 · 1인 (간헐적 진행)

GitHub ↗

C++ 게임 로직 · C++/CLI 브릿지 · WPF/MVVM UI로 책임을 분리한 3계층 구조의 테트리스. C 콘솔 코드로 시작해 단계적으로 재구성했습니다.

Contribution

  • 네이티브 ↔ 매니지드 상호운용 구현: 순수 C++ 게임 로직(TetrisCore)을 C++/CLI 래퍼(TetrisBridge)로 감싸 WPF(C#) UI에서 호출 가능하도록 연결
  • 핵심 게임 로직 설계: Fisher-Yates 셔플 기반 7-bag 랜덤, 5가지 킥 오프셋 벽킥 회전, 레벨별 드롭 속도 계산 등을 전략 패턴(Rule) 기반으로 구현. Board·Block은 파라미터로만 받아 의존성 최소화
  • 입력 처리 최적화: DAS(최초 지연 250ms)·ARR(반복 간격 40ms) 기반 키 반복 컨트롤러를 직접 구현하고, 포커스 이탈로 놓친 KeyUp 복구와 좌↔우 동시 입력 처리까지 지원
  • 협업 방식 연습: 기능별 feature/* 브랜치 → dev → main PR 병합 흐름으로 개발 (56커밋)

Review

  • C부터 C++/CLI까지: 콘솔 C 코드로 시작해 네이티브·매니지드 상호운용을 단계적으로 학습하며 언어 간 경계를 다루는 감각을 익혔습니다.

LookAtCat Vision

2026.08 – 2026.09 · 1인 (약 2주, 15커밋)

GitHub ↗

노트북 웹캠만으로 얼굴을 실시간 검출하고, 그 위치를 따라 WPF 캐릭터의 눈이 움직이는 인터랙션. (개발명 EyeTracker → LookAtCat)

Contribution

  • 멀티스레드 파이프라인 설계: 캡처·검출·렌더링을 별도 스레드로 분리하고, 처리 지연이 누적되지 않도록 큐 대신 "최신 값 하나만 lock으로 덮어쓰는" 방식으로 데이터 전달
  • 비전 처리 구현: LUT 기반 감마 보정으로 저조도 대응, dlib 68점 랜드마크, 다중 얼굴 중 추적 대상 선택(최초 최대 면적, 이후 최근접), EMA 좌표 스무딩. OpenCV ↔ dlib 이미지 변환도 직접 구현
  • 상태 기반(FSM) 캐릭터 동작 구현: Tracking → HoldLast → RandomWalk 3단 상태머신과 EMA 방향 필터로, 얼굴을 놓쳐도 자연스럽게 이어지는 시선 움직임 설계
  • 설계 전환 경험: 동공 위치 기반 시선 추적보다 얼굴 위치 기반 추적이 더 안정적이라고 판단해 최종 로직을 교체 (동공 검출은 디버그 오버레이 용도로 유지)

Review

  • 가설이 틀렸을 때의 대응: 처음 설계(동공 기반)가 최선이 아니라는 걸 직접 실행해보며 확인했고, 코드와 커밋 이력에 그 전환 과정을 그대로 남겨 판단 근거를 기록했습니다.
